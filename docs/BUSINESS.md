# 징검돌 — 유료화 정리

> 2026-09-27 · 2.1.0 기준. 결정한 것, 그 이유, 아직 남은 판단을 적는다.

## 1. 한 줄 요약

**부분유료 + 평생 1회 구매.** 무료로 끝까지 쓸 수 있고, 한 번 사면 목표 개수 제한이 풀리고
조약돌 꾸미기와 기록 내보내기가 열린다. 구독은 팔지 않는다.

| | 무료 | 징검돌 프로 (평생) |
|---|---|---|
| 조약돌과 대화하며 기록하기 | ✓ | ✓ |
| 음성 입력 · 문장 다듬기 | ✓ | ✓ |
| 지나온 길 · 모든 기록 보기/고치기 | ✓ | ✓ |
| 비밀번호 잠금 · 매일 알림 · 위젯 | ✓ | ✓ |
| 새 목표 적기 | **3개까지** | 제한 없음 |
| 조약돌 결 (6종) | 모래알 1종 | 6종 모두 |
| 기록 내보내기 (텍스트 파일) | – | ✓ |

상품 ID: `com.leeo.ReboundJournal.pro` (비소모성) — `App/ReboundJournalSpec.swift` 가 단일 출처.

## 2. 왜 이렇게 정했나

### 무엇을 팔지 않는가가 먼저다
이 앱은 막힌 날을 털어놓는 자리다. **대화·기록·돌아보기·잠금은 절대 막지 않는다.**
- 대화 한가운데 결제 화면이 뜨면 조약돌은 곁에 있는 존재가 아니라 판매원이 된다.
- 기록을 볼모로 잡으면(예: 지난 기록 30일만 무료) 사용자가 자기 이야기를 빼앗긴다고 느낀다.
- 비밀번호 잠금은 이 앱에서 안전장치다. 돈을 받는 기능이 되면 안 된다.
  (1.x 시절 계획에는 잠금이 프리미엄이었다 — 뒤집었다)

### 왜 구독이 아닌가
- **돈이 드는 곳이 없다.** 서버·AI API 비용이 없다(음성 인식·문장 다듬기 모두 기기 안). 매달 받을 근거가 약하다.
- **회고 앱의 사용 패턴은 들쭉날쭉하다.** 힘든 시기에 몰아 쓰고 괜찮아지면 뜸해진다. 구독은 뜸한 달마다
  "해지할까"를 묻게 만들고, 그게 곧 이탈이다. 평생 이용권은 다시 돌아올 때 문턱이 없다.
- **말과 행동이 맞아야 한다.** 조약돌은 재촉하지 않는다. 결제도 재촉하지 않아야 한다.
  페이월 문구에 "구독이 아니에요"를 넣은 것도 그 때문 — 결제를 망설이게 하는 가장 큰 이유를 먼저 지운다.
- 약관 URL·갱신 고지 같은 구독 심사 의무가 없다.

### 왜 이 세 가지인가
| 기능 | 전환 지점으로서 | 무료 사용자에게서 빼앗는 것 |
|---|---|---|
| 목표 개수 | 가장 자연스러운 "더 하고 싶다"는 순간. 앱을 오래 쓴 사람일수록 닿는다 | 없음 — 목표를 내려놓으면 무료로도 새로 적을 수 있다 |
| 조약돌 꾸미기 | 캐릭터 애착. "내 돌"이라는 감정에 값을 매긴다 | 없음 — 순수한 덤 |
| 기록 내보내기 | 오래 쓴 사람이 기록을 간직하고 싶을 때 | 없음 — 앱 안에서는 전부 볼 수 있다 |

세 가지 모두 **오래, 깊이 쓴 사람**에게 닿는다. 처음 온 사람은 페이월을 거의 보지 않는다.

### 페이월이 뜨는 자리 (그리고 뜨지 않는 자리)
- **뜬다:** 네 번째 새 목표를 적으려 할 때 / 잠긴 조약돌을 누를 때 / 내보내기를 누를 때 / 설정의 "알아보기"
- **안 뜬다:** 대화 중 · 앱을 열 때 · 기록을 남긴 직후 · 위젯
- 대화 중에 스스로 쪼갠 목표는 개수에 들어가지만 **막지 않는다.** (§6 쪼개기가 이 앱의 핵심 동작이라)
- 목표 한도에 닿으면 페이월부터 들이밀지 않는다. 조약돌이 먼저 상태를 말하고, **무료로 가능한 길
  (지나온 길에서 하나 내려놓기)** 을 같이 알려 준 뒤 프로를 하나의 선택지로 둔다.
- 세 번째 목표를 적을 때 "이게 세 번째예요"라고 미리 알린다. 부딪히고 나서 아는 것보다 덜 서운하다.

## 4. 측정

FeedbackHub 사용 통계로 들어온다 (`ReboundJournalSpec.analytics` → `LeeoUsageAnalytics`).

| 이벤트 | 뜻 |
|---|---|
| `gate_blocked` (key=goal) | 목표 한도에 닿음 |
| `paywall_shown` | 페이월 노출 (reason = 앞세운 기능) |
| `purchase_started` / `purchase_completed` / `purchase_failed` | 구매 퍼널 |
| `purchase_restored` | 복원 |

**봐야 할 숫자:** 한도 도달률(goal_created 대비 gate_blocked), 페이월→구매 전환율.
한도 도달이 너무 드물면(설치 대비 5% 미만) 무료 한도 3이 너그러운 것이고, 전환이 너무 낮고 이탈이
늘면 인색한 것이다. `ProFeature.freeGoalLimit` 한 줄로 조정한다 (AddGoalView 의 "세 개" 문구도 함께).
